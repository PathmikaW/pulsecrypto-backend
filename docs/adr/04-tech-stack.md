## 5. Technology Stack Summary

**As of v9.1 every version below is the version actually installed in the completed solution** (read from each repository's `package.json` and `node_modules`, with `pnpm info` used to check registry status where a claim depends on it) — not a design-time prediction. The original v7.0 table was checked against current sources at that time and several majors have since moved (pino 9→10, Vitest 3→5, ESLint 9→10 on the backend, `react-native-mmkv` 3→4, and the metrics library changed name). Where a range is declared (`^`), the _installed_ version is what was tested. Re-run `pnpm info <package> version` before upgrading anything.

**Package manager: pnpm for both repos** (ADR-X5; pnpm 12.4.2 on the development machine). Lockfile is `pnpm-lock.yaml`, committed in both repos. Any `npm install`/`npm i` elsewhere in this document should be read as `pnpm add` unless it's quoting an external tool's own doc text verbatim.

**Install rule for anything with native code:** for `react-native-reanimated`, `react-native-mmkv`, `expo-localization`, and any future native module, install via `pnpm expo install <package>` rather than plain `pnpm add`. Expo resolves the specific version known-compatible with the installed SDK automatically — this matters more than for a typical package, because an incompatible native-module version can fail at build time in a way plain semver ranges won't catch. (`pnpm expo ...` — not `npx expo ...` — is correct here: `pnpm <binary>` is a shorthand for `pnpm exec <binary>` for any locally installed package binary that doesn't collide with a pnpm builtin command.)

> **Callout — TypeScript 6.0 requires `rootDir` explicitly, where 5.x didn't.** The
> official Fastify TS scaffold's `tsconfig.json` extends `fastify-tsconfig` (3.0.0), which doesn't
> set `rootDir` — TypeScript 5.x inferred it fine, but 6.0 raises `error TS5011` ("The
> common source directory... The 'rootDir' setting must be explicitly set") as soon as
> `outDir` is also set, which the scaffold does. Fix: add `"rootDir": "src"` to
> `compilerOptions` alongside `"outDir": "dist"`. Verified by actually compiling
> (`pnpm run build:ts`, exit 0, real output in `dist/`) and starting the server, not just by the
> absence of an error message.

> **Callout — why the exact Expo SDK matters more than usual here.** Expo SDK 56 shipped with a known Hermes V1 memory regression that specifically affects apps importing `react-native-worklets` or `react-native-reanimated` — precisely the animation library ADR-M4 selects. This is resolved in SDK 57 (patched further in `expo@57.0.17`). **This project scaffolds on SDK 57, not 56**, and this isn't a cosmetic version choice — building on the affected SDK would introduce a real, documented memory issue directly into the one library most responsible for the app's core performance requirement. As of v9.1 the registry's `latest` tag is still SDK 57 and SDK 58 is only a canary; re-check before upgrading.
