| **9.0** | **Real-device testing round, post-submission.** Both repos merged to `develop` and exercised on a physical device via Expo, surfacing defects no simulator/emulator pass had caught. Added **ADR-M11** (Tab Navigation Architecture): `createNativeStackNavigator` was the original, never-reasoned-about scaffold choice for the four bottom-nav destinations; real-device use reported tab switching as laggy and flickering, traced to Stack's `navigate()` fully remounting the target screen on every switch regardless of `animation: 'none'` (which only hid the transition, not the remount cost). Replaced with `@react-navigation/bottom-tabs`, which keeps a visited screen mounted after first visit. That fix immediately surfaced a second, more serious problem, recorded as the other half of the same ADR rather than a separate one: an off-screen but still-mounted screen kept its live WS subscriptions running, confirmed by watching Telemetry's own JS-thread FPS gauge (ADR-M10) crater to 15–19 FPS while Terminal sat invisible in the background. Fixed by giving `useMarketData` an `enabled` flag, gated on React Navigation's `useIsFocused()` in both `MarketDetailScreen` and `WatchlistScreen`'s `PairRow`, so an unfocused screen's subscription is a true no-op rather than merely hidden. Also added, as addenda to their respective existing ADRs rather than new entries: (ADR-M4) `PriceText`'s flash-direction color was still driven by a plain `useState` despite the flash itself already being a reanimated worklet, forcing a JS-thread re-render on every single price tick — moved to a shared value; (ADR-M6) a fail-fast startup check that throws outside `__DEV__` if the API/WS URL isn't `https://`/`wss://`, closing a gap where a production build could have silently shipped the same plaintext defaults used for local dev; (ADR-M10) the account drawer's placeholder links were replaced from the native `Alert.alert()` (always OS-light-themed, clashing with the app's dark UI) to a themed, reanimated-driven `ComingSoonDialog`, established as the standing pattern for any future placeholder/confirmation interaction in this app. §5's Navigation row updated to reflect Bottom Tabs. |

| **9.2** | **HTTP client, common error model and retry policy.** Review of the mobile error handling found the REST path had no timeout (`fetch` has none), untyped errors, TanStack Query's default retry re-attempting permanent failures (404, schema-validation), a second private backoff implementation in the WebSocket client, and no user-visible REST failure state. Added **ADR-M12**: the `fetch` wrapper is replaced by axios behind a small `HttpClient` (10 s timeout, `AbortSignal` cancellation); every failure is normalized to an `AppError` (`network` / `timeout` / `http` / `validation` / `cancelled` / `unknown`, with a `retryable` flag and an i18n key); one retry policy (retry only when retryable, max 3, 500 ms → 8 s ±20% jitter) is wired into the query client and shares its backoff arithmetic with `WebSocketSource` (no WebSocket behavior change); localized error messages appear once retries are exhausted. Verified with 33 new unit tests (mutation-checked) and on the Android Emulator against a fake backend that logged request timing. Also corrected the last stale copies of the removed background-pair-retry claim in the mobile specs. Work branches are now named `feature/*` per ADR-X2 (the interim `chore/` name was wrong for Gitflow here). |
